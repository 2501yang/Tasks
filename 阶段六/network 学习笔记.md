# network 学习笔记

### 一、网络模型初识

1. #### 网络前世今生

- 起源：1969年ARPANET（美国国防部高级研究计划局网络）是互联网的雏形，最初用于军事和科研机构的通信。
- 发展：
- 1970s：TCP/IP协议簇诞生，成为互联网的核心通信标准。
- 1980s：NSFNET（美国国家科学基金会网络）将ARPANET扩展到大学和研究机构，形成了现代互联网的骨干。
- 1990s：万维网（WWW）由蒂姆·伯纳斯-李发明，HTTP、HTML等技术让互联网从技术工具转变为全民信息平台。
- 现状：从固定网络到移动互联网，再到物联网（loT）和5G，网络连接的设备和场景不断扩展。

2. #### 网络模型基本概念

- OSI七层模型（理论参考模型）：
1. 物理层：负责比特流的传输，定义电气、机械、功能和规程特性（如网线、光纤）。
2. 数据链路层：将比特流封装成帧，进行差错检测和纠正，实现相邻节点间的可靠传输（如以太网、Wi-Fi）。
3. 网络层：负责路由选择和寻址，实现不同网络之间的数据转发（核心协议：IP）。
4. 传输层：提供端到端的通信服务，负责数据的分段、重组和流量控制（核心协议：TCP、UDP）。
5. 会话层：建立、管理和终止应用程序之间的会话。
6. 表示层：处理数据的表示形式，如加密、压缩、格式转换（如JPEG、ASCII）。
7. 应用层：为应用程序提供网络服务接口（如HTTP、FTP、SMTP）。
- TCP/IP四层模型（实际使用的模型）：
1. 网络接口层：对应OSI的物理层和数据链路层，负责与物理网络的接口。
2. 网际层：对应OSI的网络层，核心是IP协议。
3. 传输层：对应OSI的传输层，核心是TCP和UDP协议。
4. 应用层：对应OSI的会话层、表示层和应用层，包含各种应用层协议。

### 二、TCP/IP 初识

1. #### TCP的特点

- 面向连接：在传输数据前，必须通过三次握手建立连接；传输结束后，通过四次挥手释放连接。
- 可靠传输：通过序列号、确认应答、超时重传、校验和等机制，保证数据不丢失、不重复、按序到达。
- 全双工通信：连接建立后，双方可以同时发送和接收数据。
- 流量控制：通过滑动窗口机制，根据接收方的处理能力调整发送速率，避免数据溢出。
- 拥塞控制：通过慢启动、拥塞避免、快重传、快恢复等算法，避免网络拥塞导致的性能下降。

2. #### TCP报文结构

TCP报文段由首部和数据两部分组成，首部最小长度为20字节，最大为60字节（可选字段）。

- 源端口号（16位）：发送端应用程序的端口。
- 目的端口号（16位）：接收端应用程序的端口。
- 序列号（32位）：标识本报文段数据的第一个字节的编号，用于保证数据按序到达。
- 确认号（32位）：期望收到的下一个字节的编号，用于确认已成功接收的数据。
- 数据偏移（4位）：表示TCP首部的长度（以4字节为单位）。
- 控制位（6位）：
- URG：紧急指针有效。
- ACK：确认号有效。
- PSH：接收方应立即将数据交给应用层。
- RST：重置连接。
- SYN：同步序列号，用于建立连接。
- FIN：释放连接。
- 窗口大小（16位）：用于流量控制，表示接收方还能接收的字节数。
- 校验和（16位）：用于检测报文段在传输过程中是否出错。
- 紧急指针（16位）：指向紧急数据的末尾。
- 选项（可选）：如最大报文段长度（MSS）、窗口扩大因子、时间戳等。

3. #### TCP建立连接和释放连接的过程

- 三次握手（建立连接）：
1. 客户端向服务器发送SYN报文（SYN=1，seq=x），进入SYN_SENT状态。
2. 服务器收到SYN报文后，回复SYN+ACK报文（SYN=1，ACK=1，seq=y，ack=x+1），进入SYN_RCVD状态。
3. 客户端收到SYN+ACK报文后，回复ACK报文（ACK=1，seq=x+1，ack=y+1），进入ESTABLISHED状态；服务器收到ACK报文后，也进入ESTABLISHED状态，连接建立成功。
- 四次挥手（释放连接）：
1. 客户端向服务器发送FIN报文（FIN=1，seq=u），进入FIN_WAIT_1状态，表示客户端不再发送数据。
2. 服务器收到FIN报文后，回复ACK报文（ACK=1，seq=v，ack=u+1），进入CLOSE_WAIT状态，表示服务器确认客户端的关闭请求，但可能还有数据要发送。
3. 服务器数据发送完毕后，向客户端发送FIN报文（FIN=1，seq=w，ack=u+1），进入LAST_ACK状态，表示服务器也不再发送数据。
4. 客户端收到FIN报文后，回复ACK报文（ACK=1，seq=u+1，ack=w+1），进入TIME_WAIT状态；等待2MSL（最大报文段生存时间）后，客户端进入CLOSED状态；服务器收到ACK报文后，也进入CLOSED状态，连接释放完成。

### 三、HTTP 初识

1. #### HTTP报文结构

HTTP报文分为请求报文和响应报文，两者结构相似，都由起始行、首部字段和消息体三部分组成。

- 请求报文：
1. 请求行：包含请求方法（如GET、POST）、请求URL（网址）和HTTP版本（如HTTP/1.1）。
2. 请求头：由多个键值对组成，用于传递客户端信息、请求条件等（如Host、User-Agent、Content-Type）。
3. 空行：分隔请求头和消息体。
4. 消息体：可选，用于携带请求数据（如POST表单数据、JSON）。
- 响应报文：
1. 状态行：包含HTTP版本、状态码（如200、404）和状态码描述（如OK、Not Found）。

2. 响应头：由多个键值对组成，用于传递服务器信息、响应数据类型等（如Server、Content-Type、Content-Length）。

3. 空行：分隔响应头和消息体。

4. 消息体：可选，用于携带响应数据（如HTML页面、图片、JSON）。

   #### 2.HTTP状态码的含义

HTTP状态码由三位数字组成，分为五大类：

- 1xx（信息性状态码）：表示服务器正在处理请求，需要客户端继续等待。
- 100 Continue：服务器已收到请求头，客户端应继续发送请求体。
- 2xx（成功状态码）：表示请求已成功被服务器接收、理解并处理。
- 200 OK：请求成功，服务器返回了请求的数据。
- 201 Created：请求成功，服务器创建了新的资源。
- 204 No Content：请求成功，但服务器没有返回任何数据。
- 3xx（重定向状态码）：表示客户端需要进行额外的操作才能完成请求。
- 301 Moved Permanently：资源被永久移动到新的URL，客户端应更新书签。
- 302 Found：资源被临时移动到新的URL，客户端应继续使用原URL。
- 304 Not Modified：资源未被修改，客户端可以使用缓存的版本。
- 4xx（客户端错误状态码）：表示客户端的请求存在错误，服务器无法处理。
- 400 Bad Request：请求报文存在语法错误。
- 401 Unauthorized：请求需要身份验证。
- 403 Forbidden：服务器拒绝了请求，即使客户端已通过身份验证。
- 404 Not Found：服务器找不到请求的资源。
- 5xx（服务器错误状态码）：表示服务器在处理请求时发生了错误。
- 500 Internal Server Error：服务器遇到了意外情况，无法完成请求。
- 502 Bad Gateway：服务器作为网关或代理，从上游服务器收到了无效的响应。
- 503 Service Unavailable：服务器当前无法处理请求，可能是过载或维护中。

3. #### HTTP请求/响应过程

以访问一个网页为例，完整的HTTP请求/响应过程如下：

1. DNS解析：客户端将域名（如www.xxx.com）解析为对应的IP地址。
2. 建立TCP连接：客户端与服务器通过三次握手建立TCP连接。
3. 发送HTTP请求：客户端向服务器发送HTTP请求报文，包含请求方法、URL、请求头和消息体（如果有）。
4. 服务器处理请求：服务器接收并解析请求报文，根据请求URL和方法找到对应的资源，进行处理。
5. 返回HTTP响应：服务器向客户端发送HTTP响应报文，包含状态码、响应头和消息体（如HTML页面）。
6. 浏览器渲染页面：客户端接收并解析响应报文，根据HTML、CSS、JavaScript等资源渲染页面。
7. 释放TCP连接：如果HTTP请求头中包含Connection: close，服务器会在响应后通过四次挥手释放TCP连接；如果包含Connection: keep-alive，连接会保持打开，用于后续的HTTP请求。
